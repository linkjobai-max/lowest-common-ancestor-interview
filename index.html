Lowest Common Ancestor: Three Versions You Should Be Able to Code

Lowest common ancestor (LCA) questions come in a few flavors, and knowing which one you have saves a lot of time.

In a binary search tree

Walk from the root: if both nodes are smaller, go left; if both are larger, go right; otherwise the current node is the LCA. O(h) time, O(1) space.

In a general binary tree

Recurse: return the node if it matches p or q, otherwise search both sides. If both sides return non-null, the current node is the LCA; otherwise pass up whichever side is non-null. O(n) time.

With parent pointers

Treat it like finding the intersection of two linked lists: walk up from both nodes, switching to the other start when you hit the root. They meet at the LCA.

Edge cases

One node is the ancestor of the other, and one node might not exist in the tree. Ask about the second case; if it is possible, track whether each node was actually found.

Follow-up

Many LCA queries on a static tree: mention binary lifting (O(log n) per query after O(n log n) preprocessing). You rarely need to code it, but naming it shows depth. I practice these trees with Linkjob AI coding helper.
